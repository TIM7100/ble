
整体流程：
蓝牙升级仪运行流程
1. 蓝牙芯片初始化后，若没有APP连接该蓝牙设备，则蓝牙芯片会一直维持在广播阶段，此时灯光状态为红灯闪烁；
2. 蓝牙连接成功后，会等待APP发送的指令‘1’+ 待升级的版本，接收到后根据版本是否为新版本做出不同的操作，
	2.1 升级包版本为新版本，保存版本信息回复APP“Updata”，等待蓝牙再次接收APP下发的信息；
	2.2 升级包版本已拥有，回复APP “Newest”，然后蓝牙芯片运行第4点；
3. APP下发指令‘2’+ 待下载的升级包的分段总次数，然后开始分段下载加密的升级包，数据格式为 ‘3’+ 2Byte段号 + 128Byte的升级包数据，
	下载完成后，执行第4点；
4. 调用回调函数ble_updata_app_CBs(), 实际运行函数是simpleBLEPeripheral.c文件下的函数ota_ble_updata_app_CB()；该函数通过判断升级包的状态来决定接下来的处理流程：
	4.1 FILE_AES_ING：升级包文件加密状态，之后将启动 SBP_FILE_AES_EVT 事件，对文件进行解密，既第5点；
	4.2 FILE_DOWNLOAD_ERR：升级包下载错误，此时需要断开蓝牙连接，重新连接蓝牙，之后会重新从第1点开始运行，此时灯光状态为红灯常亮；
	4.3	FILE_DOWNLOADED：升级包已准备完成，将激活升级事件SBP_AUTO_BURN_EVT，之后运行第6点
5. SBP_FILE_AES_EVT 事件，该事件会调用升级包解密函数 handle_aes_file(), 对存放在Flash中的升级包文件进行解密，解密成功后，激活升级事件SBP_AUTO_BURN_EVT运行第六点
6. SBP_AUTO_BURN_EVT事件，该事件为自动升级事件，所谓自动升级，既将触点触碰到芯片后，就会自动识别芯片并升级，不需要按键触发。此时，灯的状态为绿灯闪烁。
	蓝牙芯片会一直执行遍历地址操作，当触点触碰到芯片后，芯片地址验证通过后，就会先读取后门数据，有以下三种情况：
	6.1 若芯片已经升级，则会回复APP Code + 7（‘CHIP_NEWEST_VERSION’），此时灯光状态为绿灯常亮，然后继续执行第6点；
	6.2 若读取芯片后门数据失败，则会回复APP Code + 错误码，此时灯光状态为红灯常亮，然后继续执行第6点；
	6.3 若芯片需要升级，则会触发SBP_UPDATING_CHIP_EVTS事件，执行第7点；
7. SBP_UPDATING_CHIP_EVTS事件，该事件是 芯片升级算法的实现，不管升级成功与否，都会将升级结果以 Code + 结果码 发送给APP，之后会继续执行第6点。
8. 若中途蓝牙断开连接，则会从第1点开始运行。



具体文件和函数介绍：
1. ota_app_service.c
该文件为蓝牙接收和发送的函数集合，并用于处理蓝牙下载的升级包和对应的状态回复。

2. simpleBLEPeripheral.c
该文件用于修改蓝牙协议中的相关参数，在SimpleBLEPeripheral_Init()函数中修改。

3.UpgraderHp9Serial.c
HP9系IIC烧录接口文件。

4. file_handle.c
文件处理接口文件，该文件包含了接收加密升级包时的解密存储操作和读flash接口函数。


可能出现的错误：
1. 若运行过程中，出现芯片复位情况
	1.1 有可能是看门狗导致的复位，可以去main函数的第一条函数 watchdog_config(),修改看门狗的喂食时间；实在不行可以删除看门狗。
	1.2 堆空间不足（串口打印的数据过多时导致），可以在main文件 LARGE_HEAP_SIZE 宏定义处修改堆空间的大小
2. 存储空间不足的问题，在 魔术棒 -- Linker -- 点击Edit，可以修改存储空间的分配，用于解决存储空间不足的问题
